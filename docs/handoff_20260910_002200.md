# KEV-35: remove machine Cloudflare service-token dependency

## Scope and behavior

Node onboarding, node HTTP requests, node-control and ACP authentication use
Pax credentials without CF service tokens. Browser pairing approval and user
Cloudflare JWT/cookie flows remain in place. Cloudflared Tunnel is unchanged.

Removed daemon CF YAML/environment fields, HTTP/legacy WebSocket header
construction, ACP forwarder CF settings, and CF credential resolution in CLI,
MCP conversation, session reporting, and the shared runtime header provider.
New paxd logins configure remote auth as `none` after storing the Node Key.
Legacy database auth records are accepted without resolving CF secret refs.
No existing secret files or database tables are deleted; older binaries can
still use them during rollback. Unknown custom auth kinds still fail in the
shared provider and paxctl remote client.

The stored legacy auth schema and local control API remain readable for
compatibility. They do not enable CF service-token headers in this daemon.
Release upload scripts and browser cookie/JWT auth are separate user/admin
flows and retain their existing authentication behavior.
